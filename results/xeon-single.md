reach the same level (section 14: the large size checks scaling, it does not decide). The histogram is
limited by the store-to-load dependency of `h[x[i]] += 1`; Isocron's code is the same loop as C's

## Floating-point differences

Isocron's reduction has the fixed form of section 10 (V = 32 interleaved accumulators, blocks of 4096
elements, then a tree). Every hand-optimized (`opt`) variant implements the same form and is bit-identical.
The idiomatic variants add sequentially, from left to right, so they round differently; the reassociated

## Protocol and limits

* Inputs: random `f64` values `u * 10^e` with `u` uniform in [-1, 1) and `e` uniform in {-3..3} (so that
  the order of additions matters), and uniform random bytes. Small size: 32768 `f64` (256 KiB per array) and
  262144 bytes; large size: 10^7 elements.
* Only the kernel is timed (data loading excluded); Isocron uses `bench` (section 12), the other
  languages time the same loop and protect each result against elimination (`asm` barriers in C,
  `std::hint::black_box` in Rust, `std.mem.doNotOptimizeAway` in Zig, a global sink and `//go:noinline` in Go).
* Every Isocron call allocates its result (the histogram's 256 counters) and frees it, as the language
  semantics require; the C, Rust, Go and Zig histograms use a stack array.
* Fixed frequency: governor `performance`, turbo off (`bench/machine.sh apply`, restored afterwards).
  Effective frequency measured by `perf stat` (cycles / task clock): 3.194 to 3.195 GHz over all runs.
* Measurements are interleaved: each round runs every implementation of the kernel once, in an order
  that rotates from round to round.
* The CPU has FMA. Isocron never contracts `a * b + c` (section 10), and neither do the strict
  references: `-ffp-contract=off` in C, every product rounded by an explicit `float64(...)` in Go
  (DECISIONS D34), no contraction by default in Rust and Zig; the bit-identical results confirm it.
* AVX-512: Isocron and Zig write the accumulators as explicit vectors, which LLVM keeps in 512-bit
  registers; GCC, Clang and Rust vectorize with the default tuning of `-march=native` for this CPU,
  256-bit vectors. `results/xeon-lanes.md` compares them all with 512-bit vectors preferred.
* One thread: every program is pinned to one CPU (Isocron's thread pool then has one thread). The
  parallel variants (OpenMP, rayon, goroutines, `std.Thread`) are measured in `results/xeon.md`.
