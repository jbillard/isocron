# Isocron — block parallelism on xeon

Generated by `bench/parallel.py` on 2026-11-02T16:56:02, machine xeon (Intel(R) Xeon(R) E-2388G CPU @ 3.20GHz, 16 logical CPUs). Raw data: `results/stage2.json`.

Isocron computes the blocks of the fixed reduction form (B = 4096 elements) and of element-wise maps on a
thread pool: block j is computed by one thread and stored in its own slot, the upper levels of the tree
stay sequential, so the result is the same for any number of threads (SPEC section 10). The reference
variants: C with OpenMP (GCC), Rust with rayon, Go with goroutines, Zig with `std.Thread.Pool`; *idiomatic*
is the usual parallel reduction of each language (OpenMP `reduction(+)`, rayon `par_iter().sum()`, one chunk
per goroutine or thread), *opt* computes the blocks of the fixed form in parallel like Isocron. Clang has
no parallel variant: `zig cc` does not ship the OpenMP runtime.

Note: the matvec kernel was measured again on 2026-11-02, after DECISIONS D121 (the threads start at different rows of their chunks); every other kernel comes from the campaign.

Conditions: T threads pinned to the first hardware thread of the first T physical cores (CPUs 0,1,2,3,4,5,6,7); fixed frequency (turbo off); 30
interleaved measurements after 5 warm-up measurements, each lasting at least 100 ms.
