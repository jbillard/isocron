# Isocron — study of V (number of accumulators of the fixed reduction form)

Generated by `bench/lanes.py` on 2026-11-01T15:50:14, machine xeon (Intel(R) Xeon(R) E-2388G CPU @ 3.20GHz). Raw data: `results/xeon-lanes.json`.

SPEC section 10 fixes V, the number of interleaved accumulators of the fixed reduction form (V = 32 since
this study; it was 16, provisional) and B = 4096 elements per block. This study measures V = 16, 32 and 64
with three instruction sets: SSE4.2 without AVX (`xmm` registers, 2 doubles, 16 registers: the code of the
Celeron J3455 of the POC, CPU `goldmont` for every compiler, run on this machine), AVX2 only (`ymm`, 4
doubles, 16 registers) and AVX-512 (`zmm`, 8 doubles, 32 registers), for Isocron (`iscc build --lanes V
--isa ...`) and for the hand-optimized fixed form in C (GCC, Clang), Rust and Zig built with the same V.
When the accumulators and the loaded elements do not fit in the registers, Isocron and the hand-optimized
references update the accumulators in several passes over each block, which does not change the result
(DECISIONS D56). Go has no SIMD and is left out. For each V, every output is compared bit for bit with the
reference interpreter run with the same V (`iscc run --lanes V`); results differ from one V to another,
which is why V belongs to the language and not to the compiler.

Conditions: pinned to CPU 7; fixed frequency (turbo off); 30 interleaved measurements after 5 warm-up measurements, each lasting at
least 100 ms. Times are per call.
